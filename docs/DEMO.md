## 二、预置数据

演示数据由 `sql/demo_reset.sql` 重置，特征如下（**刻意设计**，为了每个演示点都有数据支撑）：

| 设计 | 目的 |
|---|---|
| 共 12 条，每页 5 条 → 3 页 | 分页控件能完整展示「首页/上一页/页码/下一页/末页」 |
| 状态分布：待办 5 / 进行中 4 / 已完成 3 | 状态筛选每项都有结果，不会出现空页 |
| 标题含「报告」的恰好 2 条 | 模糊查询能命中且不铺满整页 |
| id=1 是「待办」 | 演示「开始」流转用 |
| id=2 是「进行中」 | 演示「完成」流转用 |
| id=3 是「已完成」 | 演示「重新打开」用 |
| 有 1 条标题超长（接近 255 字） | 演示边界（刚好通过 / 超 1 字被拒） |

## 四、场景 1：正常业务链路（2.5 分钟）

**台词**：先走一遍用户真实会做的事，确认主流程没毛病。

| 步 | 操作 | 预期 | 讲解要点 |
|---|---|---|---|
| 1 | 无痕窗口打开 `/task/list` | **302 → /login** | 拦截器生效；登录后会自动跳回原地址 |
| 2 | 输入 `admin / 123456` 登录 | 进入列表，右上角 **DEV** 徽标 | 徽标来自 `application-dev.yml`，证明 profile 生效 |
| 3 | 看列表底部 | 共 12 条 · 第 1/3 页 | 分页信息来自 `IPage` |
| 4 | 名称填「报告」→ 查询 | 命中 **2 条** | 模糊查询（`LIKE`），输入框回显条件 |
| 5 | 点「下一页」 | 仍是筛选结果 | **翻页保留筛选条件**（链接带 `title`） |
| 6 | 点「重置」 | 回到 12 条 | 清除条件 |
| 7 | 点「＋ 新增任务」→ 填 标题/优先级/状态/日期 → 提交 | 回到列表，顶部「新增成功」 | 这是 **PRG**：POST 后 302 再 GET，刷新不会重复插入 |
| 8 | **按 F5 刷新** | 提示消失，数据不变 | Flash 属性只消费一次；数据不重复 |
| 9 | 对 id=1（待办）点「开始」 | 状态变「进行中」 | 状态机：只有待办能 start |
| 10 | 对 id=1 再点「完成」 | 状态变「已完成」 | 进行中 → 已完成 |
| 11 | 对 id=1 点「重新打开」 | 回到「进行中」 | reopen 只允许从已完成出发 |
| 12 | 点「修改」→ 改标题 → 提交 | 列表更新，提示「修改成功」 | 修改走 `/task/edit/{id}` 路径变量 |
| 13 | 点「删除」→ 确认 | 记录消失，总数 -1 | 删除只接受 POST |

> **停顿点**：第 8 步的 F5 一定要做，这是「PRG 到底解决什么问题」最直观的一秒。

## 五、场景 2：边界与报错（2.5 分钟）

**台词**：正常流程谁都能跑通，下面这些才是日常真正会遇到的。

| 步 | 操作 | 预期 | 讲解要点 |
|---|---|---|---|
| 1 | 新增时**标题留空**直接提交 | 回到表单，标题下方红字「任务名称不能为空」 | `@NotBlank` + `th:errors` **逐字段**回显 |
| 2 | 日期留空提交 | 日期下方「截止日期不能为空」 | 多个字段同时报错，各自显示 |
| 3 | 日期填 `2026-02-31` | 「截止日期不能为空」或格式提示 | 非法日期不会 500 |
| 4 | 标题粘贴 256 个「测」 | 「任务名称长度不能超过 255 个字符」 | `@Size(max=255)` 边界 |
| 5 | 标题粘贴 255 个「测」 | **提交成功** | 证明边界是「≤255」而不是「<255」 |
| 6 | 地址栏手改 `?page=abc` | 正常显示第 1 页 | 参数容错：不报 400，静默回落 |
| 7 | 手改 `?page=999` | 自动跳到**最后一页** | 越界回退，永不空白页 |
| 8 | 手改 `?status=99` | 视为「全部」 | 非法枚举值被忽略 |
| 9 | 新窗口直接访问 `/task/delete/1` | **405** + 友好错误页 | 删除只映射 POST，GET 被 Spring 拒绝 |
| 10 | 终端执行 `curl -i http://localhost:8084/api/tasks` | **302** 到 `/login` | API 也要求登录（只读但含业务数据） |
| 11 | 终端执行 `curl -i http://localhost:8084/api/tasks/99999`（带 Cookie） | **404** + `{"code":404,...}` | API 错误码与 HTTP 状态一致 |

> **停顿点**：第 9 步的 405 和第 10 步的 302，是「安全默认值」的两个例子。
> 强调：这两个行为**不是靠开发者记得写，而是框架结构上就保证了**。

## 六、场景 3：「异步 / 延迟」表现（1 分钟）

**必须提前说明的事实**：当前版本是**同步阻塞**的，没有真正的异步处理链路
（没有 `@Async`、没有消息队列、没有定时任务）。所以这一节演示的是
**「跨请求的状态传递」**，而不是异步任务。

| 演示点 | 操作 | 观察 | 说明 |
|---|---|---|---|
| 一次性消息 | 新增成功后**立刻按 F5** | 提示消失 | Flash 存在 Session，读完即销毁 —— 这是「跨重定向的一次性状态」，机制上与异步回调里回写状态同源 |
| 事务的「要么全成要么全不成」 | 状态流转时制造失败（见下） | 数据保持原样 | `@Transactional` 保证「查状态→判合法→改状态」三步原子 |

**制造一次事务失败**（不修改数据）：在另一窗口把同一条任务先改成「已完成」，
再回到原窗口点「开始」—— 会提示「状态更新失败：只有「待办」状态的任务可以开始」，
刷新后数据没有被改坏。

> **诚实提示（答辩时主动说）**：如果被问到「异步处理」，标准回答是：
> 「当前没有异步链路，任务都是同步完成的。要做异步，最小改造是
> 把通知/导出这类旁路操作抽成 `@Async` 方法并配独立线程池；
> 但状态流转本身**不应该异步**，因为用户需要立刻看到结果。」

## 七、场景 4：API 与文档（1 分钟）

```bash
# 1) 登录拿 Cookie
curl -c cookie.txt -X POST http://localhost:8084/login \
     -d 'loginName=admin&loginPwd=123456'

# 2) 分页查询（只取 3 条）
curl -b cookie.txt 'http://localhost:8084/api/tasks?page=1&size=3'

# 3) 按名称模糊 + 按状态筛选
curl -b cookie.txt 'http://localhost:8084/api/tasks?title=%E6%8A%A5%E5%91%8A&status=0'

# 4) 查不存在的 id，看错误码
curl -i -b cookie.txt 'http://localhost:8084/api/tasks/99999'
```

**讲解要点**：
- 返回统一结构 `{code, message, data}`，`code=0` 表示成功
- 这个手册**不是手写的**：`docs/API.md` 由 `/v3/api-docs` 的 JSON 渲染而来
- 浏览器打开 `/swagger-ui/index.html` 可以直接点「Try it out」调试

## 九、场景 6：Code Review 拦住了什么（1.5 分钟）

打开 `docs/CODE-REVIEW.md`，只讲两条最有说服力的：

1. **`pageSize` 回退成魔法值 10** —— 代码能跑、测试也绿（因为我最初的断言只检查「被修正了」，
   没检查「修正成多少」）。是人工评审发现「行为不连续」，然后**代码和测试一起改**。
2. **死代码异常处理器** —— AI 生成了一个永不触发的 `@ExceptionHandler`。
   能编译、能启动，但 Boot 默认根本不抛那个异常。

**收尾金句**：
> 测试验证的是「我想到的场景」，评审验证的是「我没想到的场景」。
> AI 把写代码的成本降下来了，但没有把「怀疑」的成本降下来。

## 十、兜底预案

| 意外 | 现场处理 |
|---|---|
| 数据库没起 | `net start MySQL80`，等 10 秒重启应用 |
| 端口 8084 被占 | `java -jar ... --server.port=9090`，并改用新端口 |
| 演示数据被改乱 | 重跑 `mysql ... < sql/demo_reset.sql`，刷新页面 |
| 应用启动失败 | 看 `mvn clean package` 是否通过；`target` 有残留就 `clean` |
| 网络不通（依赖下载） | 提前 `mvn -o clean package` 全离线构建过一次，依赖已在本地仓库 |
| 投影看不清 | 浏览器 Ctrl+加号放大到 125% |
| 时间不够 | 砍掉场景 3 与场景 6，保留场景 1/2/5 |
